# Reviewing existing instrumentation for correlation gaps

Use this when an app already exports traces, logs, metrics and business events and the question is "what is still missing to detect and explain an incident?" Read the code paths, not the observability document: a mature contract can describe signals the code never populates. Each finding needs file:line evidence, the detection question it blocks, and the bounded fix.

## Walk every signal from emitter to consumer

1. Outcome vocabularies. Find each place a caller passes an outcome/category to a recorder and compare the literal values with the recorder's allowlist. Mismatched vocabularies silently collapse to `other`/`APPLICATION_ERROR`. Test the mapping end to end (caller literal → exported value), not only the recorder with hand-written valid values.
2. Error classification. Locate the API error boundary and every dependency call. Check that the application error code (not just HTTP status) reaches the server span (`error.type`), the completion log and a bounded metric dimension. Status 503 from an auth outage, an LLM quota and a maintenance lock must be distinguishable. Normalize vendor codes into the bounded set: Firebase `messaging/…`/`auth/…` strings, gRPC numeric codes (`ABORTED`, `DEADLINE_EXCEEDED`, `RESOURCE_EXHAUSTED`), `AbortSignal` `TimeoutError`, schema/parse failures. A catch-all share above a few percent of error spans means classification is incomplete.
3. Dependency spans. Each external call span should carry its semantic attributes: `db.system.name` plus `db.collection.name`/`db.operation.name`; `gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`/`output_tokens`, `gen_ai.response.finish_reasons`; `server.address`, `http.response.status_code`. Discarded usage metadata is lost cost and quota evidence. A bare span name with a duration cannot answer "which model/collection/topic regressed".
4. Worker and queue health. For every scheduled or queued job confirm a counter per outcome, a histogram for processing lag (process time − due time) and gauges for backlog depth and oldest pending age. Numeric attributes on a completion log are not metrics, and attributes outside the log allowlist are dropped without warning.
5. Browser failure path. Check that render-boundary errors, unhandled rejections and API failures are reported to RUM (`reportError`/`reportCustomError`) with a bounded code and the server `request.id` as the hint; disabling automatic action detection also removes automatic error-to-action attribution. Confirm the RUM application declares every custom action/session property name the code sends; undeclared properties are discarded silently.
6. Browser→backend linkage. Confirm the ingress extracts the header the RUM agent actually sends (W3C `traceparent` vs vendor headers), same-origin propagation is enabled for the API path, and a tenant query joins one RUM action to its server span by `request.id`. Document it as unverified until that join succeeds.
7. Business events for analytics. Committed-write summaries (`records.written`, `records.stage_changed=1`) prove integrity but cannot answer funnel, conversion or outcome-mix questions. Check for semantic events carrying bounded from/to state, outcome, kind, entity ID and actor; check that rejected attempts (conflict, denied, rate-limited, maintenance lock) are visible as bounded events or logs, not only as a status code count.
8. Resource identity. For serverless/container runtimes confirm `cloud.provider`, `cloud.platform`, `cloud.region`, `faas.name`, `faas.version`/revision so a regression can be tied to a specific deployed revision; disabling auto-detection requires setting these explicitly.
9. Split log sinks. Platform `console.*` logs that carry `requestId` but no trace/span ID cannot be joined from the tenant side. Either route them through the OTel logger or add the active trace context to the JSON.
10. Routing and segmentation contracts. If the tenant routes by `service.namespace`/`service.name`/`event.provider`, every signal including business, deployment and CI events must carry those fields, and synthetic/verification traffic must be distinguishable (separate namespace or environment) from production views.

## Report format

Group findings as: correctness bugs (wrong data exported), missing error correlation, dependency/database semantics, worker/queue metrics, business-event analytics, browser failure path, linkage verification, resource identity. For each give severity, evidence location, what it prevents detecting, the bounded fix and the privacy constraint it must keep. Reference existing tracked work instead of duplicating it.

# Completion and handoff

- Review agreed behavior, contracts/policy, permissions/data scope, migrations, UI/settings, telemetry and meaningful tests for every feature; record inapplicable layers.
- Maintain README/setup, security, architecture/API, settings, design, testing/case catalog, observability/recovery, release impact, changelog and user workflows/troubleshooting as applicable. Every setting documents default, personal/workspace scope, permissions, contract, effective timing and limits.
- Apply [service continuation](services.md), [evidence](evidence.md), [delivery/release](github-release.md) and [safety](safety.md) at their owning files; do not restate them in project workflows.
- Inspect Git status, branch, diff and staged/untracked artifacts. Verify issue/PR relationship, current-head reviews/checks, remote merge and issue resolution, plus applicable SDLC delivery/searchability and deployment-to-runtime proof.
- Report usable outcome, actual checks and identities, secrets/setup still needed, and concrete remaining blockers. Published is not local-only. Stop at completion or an explicit external dependency, not an arbitrary partial result.
- Validate skill behavior against [scenarios](scenarios.md), with no external side effects.

# Project Handoff

Start with skills/catalog.json. Select the workflow skills for the task and service skills whose source paths, entrypoints, contracts or dependencies overlap the change. Read their continuation files before acting. Treat stored notes as pointers to verify, not current truth or authorization.

Before stopping, update each affected continuation file: current scope, linked issue/PR, last verified revision, completed behavior, exact tests/results, deployment and telemetry states, blockers, unresolved decisions, and a concrete next action with acceptance criteria. Keep plans separate from evidence and include only safe durable artifact references. No credentials or customer content.

Update catalog lastReviewedRevision only to a real revision you inspected; pending is valid when unavailable. On resume inspect Git/PR/CI and current source; invalidate stale claims when reality differs. A skill does not grant delegation, merge or deployment permissions.

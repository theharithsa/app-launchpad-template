# Project Design

Read the brief, decisions, coverage and affected service skills. Confirm the actual audience, primary journey and acceptance criteria; resolve missing product, identity, branding, privacy and stack decisions with the human.

For UI work record tokens, reusable components, responsive behavior, accessibility, keyboard/focus flow and loading/empty/error/denied states. For service work record boundaries, versioned contracts, authorization, ownership, concurrency and failure semantics before implementation. Avoid inventing backend services for static pages.

Update the affected service's contracts/decision links and continuation record with approved design, unresolved choices and the next implementable slice. Use the [build guidance](../../.agents/skills/app-launchpad/references/build.md) for contract and UI details.

For explanatory visuals in docs, websites, onboarding or app content, use the bundled [Ian/Xiaohei illustration skill](../ian-xiaohei-illustrations/SKILL.md) where it clarifies meaning. The standing style preference is already approved. Plan placement and one core idea per image, choose the smallest useful set, and follow [illustration policy](../../docs/illustrations.md). Preserve explicit brand/style constraints; provide accessible text equivalents and verify responsive integration.

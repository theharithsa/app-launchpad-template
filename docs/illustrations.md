# Explanatory illustration policy

Ian Xiaohei Illustrations is the default skill for useful explanatory images across README/docs, websites, onboarding, application explainers and related project content. This is a standing user preference; no repeated style confirmation is needed for suitable use. Explicit project requirements take precedence.

## Select the visual for its purpose

Use Ian/Xiaohei illustrations for a concept, workflow, state, metaphor or pitfall that becomes clearer with an image. Plan placement and meaning before generation. Skip images that only decorate or repeat adjacent text. Use precise diagrams, charts, code examples or actual synthetic screenshots where accuracy or the reader's task calls for them. Do not replace logos/brand assets or force this style into every screen, document or slide.

The bundled skill is [skills/ian-xiaohei-illustrations/SKILL.md](../skills/ian-xiaohei-illustrations/SKILL.md), including its mode-specific reference files and calibration examples. Read those required by the mode. The project preference broadens the suitable destinations to docs/sites/app explainers and chooses only the number of images needed, overriding generic fixed image counts; it does not change the skill's original composition, QA or safe-save rules. Calibration examples are not production assets to reuse.

## Generation, integration and continuation

1. Read the real content, approved design and affected service skill. Select the minimum useful placements and one core idea for each. Show the compact placement/spec table when generating; do not turn it into an extra approval checkpoint.
2. Use the available image generation tool, following the skill's mode and QA rules. If the tool is unavailable, leave generation explicitly blocked and continue useful independent work. Do not substitute a fake asset or silently use an API requiring unapproved credentials/costs.
3. Save approved project assets under `assets/<topic>-illustrations/` unless the project specifies another destination. Keep original outputs, avoid overwriting existing assets, and integrate the actual saved file. Optimize delivery with the chosen stack while preserving readable labels and aspect ratio.
4. Add useful alt text and adjacent text for essential meaning. Verify labels, white-background contrast within the consuming theme, small-screen readability, dimensions and loading behavior in the actual destination. English labels are the skill default; explicit product language takes precedence.
5. Record placement, meaning/spec or prompt reference, asset path, QA outcome and reviewed revision in the affected service/docs continuation. Use synthetic content, never secrets or customer data. Generated images are explanatory assets, not evidence of runtime or release behavior.
